# Требования FireCharts

## Назначение

Самостоятельно размещаемый веб-инструмент наблюдения за ликвидностью Binance Spot.
Используются только публичные market data, без торговых ключей, платных API и сделок.

## Публичный график

- BTCUSDT Spot, периоды1D/1W, автообновление15s, история около14дней.
- Depth5000 примерно раз в15s согласуется с непрерывным diff-потоком по updateID.
- Карта — средний объём заявок, взвешенный временем. Порог после ценовой агрегации.
- Пунктир — наблюдаемые границы полного диапазона снимка. После gap неизвестные
  дальние уровни не считаются актуальными, неизвестные участки отмечены явно.
- Минутные summaries ускоряют чтение; raw и минимальные опорные снимки сохраняются
  для восстановления границы окна. Один writer на архив.
- Binance OHLC и поток агрессивных покупок/продаж за5/15/60 завершённых минут.
- CVD по размерам исполнений, абсолютный/нормализованный; группы не являются кошельками.
- Ручные шкалы цены/объёма, управление мышью/клавиатурой/жестами.

## Личные пары

- Отдельная /private со случайной ссылкой владельца и серверной проверкой сессии.
- Публичная / не показывает личную панель даже при наличии cookie владельца.
- До4 дополнительных Binance Spot пар; каждая имеет отдельный writer и архив.
- Сбор с текущего момента, rolling6h, очистка раз в минуту плюс минимальная опора raw.
- Ручные настройки сохраняются по символу, включая удаление и повторный запуск.
- Валюта объёма и точность соответствуют паре; USDT-конвертация не придумывается.
- Удаление останавливает проверенный процесс, захватывает locks и удаляет только
  каталог выбранной пары. Публичный BTC нельзя удалить через личный API.

## Bybit Spot

Текущая разница последних цен Bybit − Binance той же пары. На графике и в архиве
остаются исходные Binance цены. Tooltip показывает приблизительный эквивалент
уровня по текущей разнице, в том числе при просмотре истории. История спреда не
хранится. Нет пары/свежих котировок — нет пересчёта.

## Развёртывание и доступ

Python3.11+, проверенная среда Ubuntu24.04/Python3.12/systemd. Web слушает loopback,
публикуется через HTTPS reverse proxy. Основной сборщик и web — разные сервисы;
личные сборщики управляются web. API проверяет роль до личных операций, POST
проверяет Origin и JSON. Ограничены вычисления, worker pool, матрицы и кэши.

## Границы

Нет MTF, Telegram, торговли, фьючерсов, идентификации кошельков или восстановления
неизвестной истории depth по текущему стакану. Наблюдаемая ликвидность не гарантирует
исполнение сделки. Нет полноценной многоарендной системы: один владелец, публичный BTC.

## Проверка результата

Unit/JS-проверки и синтаксис проходят; HTTP доступ/ошибки/границы ролей проверены.
Браузерные сценарии покрывают desktop/mobile и личные пары. Live-сбор не создаёт
второго writer. Измерения ресурсов относятся к конкретной дате/конфигурации,
а не гарантируют пиковую нагрузку или ёмкость произвольного VPS.
