# Веб-график и хранение

## Компоненты

- `collector.py`, `core.py`, `depth_refresh.py`: Binance depth/aggTrade,
  согласование снимков, агрегация и запись основного архива.
- `storage.py`: SQLite/raw/checkpoints, retention и writer lock.
- `market.py`: отдельный восстанавливаемый кэш OHLC и статистика taker-потока.
- `webdata.py`: read-only согласованный snapshot и time-weighted агрегация.
- `web.py`, `updates.py`: loopback HTTP, bounded caches/worker pool и revision patches.
- `static/app.js`, `chart.js`, `updates.js`: UI, Canvas, Lightweight Charts, жесты.
- `private_access.py`, `private_pairs.py`, `pairs_worker.py`: доступ владельца и личные пары.
- `spread.py`: текущая разница Binance/Bybit Spot без нового архива.

Основной collector запускается supervisor. Web не пишет основной archive.sqlite;
его market worker пишет только market.sqlite. Каждый личный архив имеет свой
единственный writer. Дублировать collect для теста при работающем collector нельзя.

## Данные

Основной BTC сохраняет около14дней: raw, минутные summaries и минимальную опору
для восстановления границы. Средние объёмы взвешены временем, фильтр применяется
после ценовой агрегации. Цена/объём private поддерживают точность выбранной пары.

REST depth5000 примерно раз в15s согласуется с buffered diff по updateID.
Пунктир отражает реальные моменты и границы полученных снимков. После потери
последовательности неизвестные дальние уровни отбрасываются, gap не закрашивается
выдуманными данными. Данные за пределами полного снимка частично наблюдаемы.

OHLC Binance рисуется поверх карты локальной Lightweight Charts5.2.1.
При отдалении свечи агрегируются в5/15/60минут с сохранением high/low.
Покупки/продажи — только полные завершённые интервалы5/15/60минут.

## HTTP и обновления

`/api/chart?mode=1d|1w&step=200&range=5` — публичный BTC snapshot.
Step публичной карты25–2000, кратно25; range±0.5–20%, шаг0.5.
Первый ответ полный, далее since=revision даёт delta/unchanged при совместимой
геометрии. Потерянная ревизия/смена сетки возвращает полный snapshot.
UTC-колонки2min/15min; границы, свежесть и исправления старых значений учитываются.
Автообновление сохраняет view и не меняет данные во время активного жеста.

Роли/операции личных пар описаны в [private-pairs.md](private-pairs.md).
Статика выдаётся по allowlist, архивы/логи/ссылки через HTTP не раздаются.
`/healthz` проверяет web, `/readyz` — актуальность основного collector.

`/api/spread` — текущая разница Bybit/Binance BTC; private-вариант проверяет роль
и активную пару. Параллельные REST last-price замеры кэшируются примерно15s;
замер дольше5s отбрасывается, значения старше45s не используются. Это приблизительное
соответствие, не синхронные исполнения и не исторический спред.

## Навигация

На ПК mouse drag в карте двигает время и цену одновременно, даже при полном
ценовом окне. За пределами загруженных цен пусто, tooltip показывает отсутствие
данных. Правая шкала меняет ценовой масштаб, двойной клик/сброс возвращает view.
Canvas сохраняет клавиатурный фокус без внешней рамки.

Touch: один палец двигает время, два масштабируют время/цену. Удержание550ms
включает inspection с перекрестием, смещением от пальца и лупой. Движение до
активации отменяет удержание. CVD drag остаётся горизонтальным.

## Проверки и эксплуатация

Команды установки и обновления находятся в [README](../../README.md).
Полная установка на чистом VPS и фактический reboot не заменяются unit-тестами.
Браузер: tests/browser.mjs, tests/resume-browser.mjs; нужны отдельно установленные
Playwright/Chromium и переменные PLAYWRIGHT_MODULE, CHROMIUM_EXECUTABLE,
MTANALOG_BROWSER_URL. Private-browser создаёт/удаляет свою тестовую пару;
использовать только в изолированной среде и после чтения сценария.

Для штатного web service использовать systemctl start/stop/restart под root;
SIGTERM при Restart=on-failure не означает автоматический restart.
Backup сохраняет три SQLite+tracked-source копии, не raw и не личные архивы.
Копии на том же диске не защищают от потери сервера.
