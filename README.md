# FireCharts

Карта ликвидности Binance Spot в браузере. Показывает скопления лимитных заявок,
движение цены и агрессивные покупки и продажи.

Работает на вашем сервере. API-ключи и платные подписки не нужны.

## Возможности

- Карта ликвидности BTC/USDT со свечами, обновление каждые 15 секунд.
- Просмотр за день или неделю, хранение истории около 14 дней.
- Ручная настройка ценового диапазона и фильтра объёма.
- CVD — накопленная разница покупок и продаж, отдельно по размеру исполнений.
- Управление мышью и жестами на телефоне.
- Закрытая страница владельца для сбора других пар Binance Spot.
- Текущая разница цен Binance и Bybit Spot.

**История ликвидности накапливается после запуска.** Скачать прошлую карту
с биржи нельзя. Свечи загружаются отдельно и могут появиться раньше карты.

## Требования и расход ресурсов

Рекомендуемая конфигурация: **Ubuntu 24.04, 2 vCPU, 4 ГБ RAM и от 20 ГБ свободного диска**.

Понадобятся доступ по SSH, права `root` для установки и домен для HTTPS.
Сервер должен иметь доступ к публичным API Binance; для сравнения цен — также к Bybit.

| Три резервные копии | ≈ 1,7 ГБ |
| Основная база SQLite | ≈ 563 МиБ |
| Опорные снимки | ≈ 72 МиБ |
| Данные двух дополнительных пар | ≈ 126 МиБ |

За короткий пятисекундный замер процессы использовали около 6% одного ядра.
Это текущая нагрузка, а не нагрузочный тест. Размеры каталогов приблизительные,
как в выводе `du -h` (степени 1024).

Файловый кэш ОС учитывается отдельно от RSS. Расчёт графиков и резервное
копирование увеличивают потребление ресурсов, поэтому размер VPS выбирайте с запасом.
Объём данных зависит от активности рынка и количества пар.
При свободном месте менее 3 ГиБ сбор приостанавливается.

## Установка

В примере используются пользователь `firecharts` и папка
`/home/firecharts/firecharts`. Команды рассчитаны на Ubuntu 24.04 с systemd.

### 1. Подготовьте сервер

Подключитесь по SSH под `root`:

```bash
apt update
apt install -y git python3 python3-venv ca-certificates curl nano

adduser firecharts
loginctl enable-linger firecharts
```

Задайте пароль нового пользователя. Остальные поля можно пропустить клавишей Enter.

### 2. Установите проект

Откройте **новую SSH-сессию под пользователем `firecharts`**:

```bash
ssh firecharts@IP_ВАШЕГО_СЕРВЕРА
```

Скачайте проект и установите зависимости:

```bash
git clone https://github.com/94la/firecharts.git
cd firecharts

python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock.txt
```

Проверьте установку:

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Если проверка завершилась словом `OK`, запустите постоянный сбор:

```bash
.venv/bin/python deploy/install-supervisor.py
```

Сбор продолжится после закрытия SSH и будет автоматически запускаться после
перезагрузки сервера. Путь к проекту не должен содержать пробелов.

### 3. Запустите сайт

В SSH-сессии под `root` выполните:

```bash
python3 /home/firecharts/firecharts/deploy/install-web.py --user firecharts
```

Проверьте:

```bash
curl --fail http://127.0.0.1:8790/healthz
```

Ожидаемый ответ:

```json
{"ok": true}
```

### 4. Подключите домен и HTTPS

Создайте DNS-запись типа **A**, указывающую ваш домен или поддомен на IPv4 сервера.

Установите Caddy по [официальной инструкции для Ubuntu](https://caddyserver.com/docs/install#debian-ubuntu-raspbian).

Под `root` откройте конфигурацию:

```bash
nano /etc/caddy/Caddyfile
```

Добавьте блок, заменив `charts.example.com` своим доменом:

```caddyfile
charts.example.com {
    encode zstd gzip
    reverse_proxy 127.0.0.1:8790
}
```

Если Caddy уже обслуживает другие сайты, сохраните их блоки.

Проверьте и примените конфигурацию:

```bash
caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
systemctl reload caddy
```

Сервер должен принимать входящие соединения на портах **80 и 443**.
Порт **8790** открывать наружу не нужно.

Откройте свой домен в браузере. Карта начнёт наполняться по мере сбора данных.

## Как пользоваться

Выберите **1D** или **1W**. В настройках задайте ценовой шаг, диапазон
и минимальный объём заявок.

- Светлее участок карты — больше наблюдаемая ликвидность.
- Пунктир — границы полного диапазона полученного снимка стакана.
- Серые участки — пропуски данных.

**На ПК:** перетаскивание левой кнопкой двигает карту по времени и цене,
колесо меняет масштаб. Перетаскивание правой ценовой шкалы меняет масштаб цены.

**На телефоне:** свайп двигает время, два пальца меняют масштаб,
удержание показывает значения.

Двойной клик или кнопка сброса возвращает исходный вид.

<details>
<summary>Что показывают покупки, продажи и CVD</summary>

Блок «Покупки / продажи» показывает агрессивные исполнения за последние
завершённые 5, 15 или 60 минут.

CVD накапливает разницу агрессивных покупок и продаж. Отдельные линии
группируют исполнения по размеру сделки. Эти группы не определяют кошельки,
конкретных участников или их общий капитал.

</details>

<details>
<summary>Как работает сравнение с Bybit</summary>

График, свечи и ликвидность относятся к Binance.

Под картой показана текущая разница спотовых цен **Bybit − Binance**.
При наведении или касании уровня появляется его примерный эквивалент на Bybit.

Пересчёт использует текущую разницу цен, в том числе при просмотре старого
участка. Это не историческая цена и не стакан Bybit.
Если пары на Bybit нет или свежие котировки недоступны, пересчёт не показывается.

</details>

## Другие пары — доступ владельца

Обычный адрес сайта показывает BTC/USDT. Для дополнительных пар предусмотрена
отдельная личная ссылка.

<details>
<summary>Создать личную ссылку и запустить сбор других пар</summary>

Под пользователем `firecharts` выполните:

```bash
cd /home/firecharts/firecharts

.venv/bin/python -m mtanalog private-link \
  --origin https://charts.example.com \
  --output output/private-owner-link.txt
```

Замените домен своим. Посмотрите созданную ссылку:

```bash
cat output/private-owner-link.txt
```

**Ссылка даёт права владельца. Не публикуйте её.** Повторное выполнение команды
отзовёт предыдущую ссылку.

На личной странице можно:

- Запускать до четырёх дополнительных пар одновременно.
- Просматривать последние 6 часов.
- Сохранять настройки шкал отдельно для каждой пары.
- Останавливать сбор и удалять данные выбранной пары одной кнопкой.

Сбор продолжается при переключении пар и закрытии браузера. Данные старше
окна хранения автоматически удаляются. Объёмы указаны в валюте котировки пары:
например, для ETH/BTC — в BTC.

</details>

## Обслуживание

<details>
<summary>Проверить состояние, остановить или перезапустить</summary>

Команды сборщика выполняются под пользователем `firecharts` из папки проекта:

```bash
cd /home/firecharts/firecharts
```

| Действие | Команда |
|---|---|
| Состояние сбора BTC | `.venv/bin/python -m mtanalog status` |
| Остановить сбор BTC | `.venv/bin/python -m mtanalog stop` |
| Возобновить сбор BTC | `.venv/bin/python -m mtanalog start` |
| Создать резервную копию | `.venv/bin/python -m mtanalog backup` |
| Посмотреть журнал сборщика | `tail -n 50 data/collector.log` |

Управление сайтом — под `root`:

```bash
systemctl status mtanalog-web.service
systemctl restart mtanalog-web.service
journalctl -u mtanalog-web.service -n 50
```

Личные пары управляются через личную страницу. Команды остановки BTC их не останавливают.

</details>

<details>
<summary>Обновить проект</summary>

Если запущены личные пары, сначала остановите сайт под `root`. Их данные
сохранятся, а сбор возобновится после запуска сайта:

```bash
systemctl stop mtanalog-web.service
```

Затем под пользователем `firecharts`:

```bash
cd /home/firecharts/firecharts

.venv/bin/python -m mtanalog stop
.venv/bin/python -m mtanalog backup

git pull --ff-only
.venv/bin/python -m pip install -r requirements.lock.txt
.venv/bin/python -m unittest discover -s tests -v
```

При ошибке любой команды остановитесь и разберитесь с причиной.
Не продолжайте обновление поверх ошибки.

Если проверки завершились успешно:

```bash
.venv/bin/python -m mtanalog start
```

Под `root` запустите сайт:

```bash
systemctl start mtanalog-web.service
```

Не удаляйте `data/`: там собранная история. Если вы меняли исходники
самостоятельно, сохраните изменения до `git pull`.

</details>

<details>
<summary>Если что-то не работает</summary>

| Проблема | Что проверить |
|---|---|
| Сайт не открывается | DNS, порты 80/443, состояние Caddy и web service |
| Свечи есть, карта пустая | Статус сбора, время накопления и фильтр объёма |
| Сборщик неактивен | Команду `status` и журнал `data/collector.log` |
| Не хватает места | Свободный диск; не удаляйте рабочую папку `data/` |
| Bybit недоступен | Наличие этой Spot-пары на Bybit и доступ к API |
| Команда не находит `.venv/bin/python` | Перейдите в `/home/firecharts/firecharts` |

Проверка сайта внутри сервера:

```bash
curl --fail http://127.0.0.1:8790/healthz
```

Проверка готовности сборщика:

```bash
curl --fail http://127.0.0.1:8790/readyz
```

`healthz` проверяет работу сайта. `readyz` также учитывает актуальность данных сборщика.

</details>

## Важно о данных

Карта показывает наблюдаемые заявки: они могут изменяться или отменяться.
За пунктирными границами полнота стакана не гарантируется.

Основной архив хранится около 14 дней, личные пары — последние 6 часов.
Резервные копии на том же сервере не защищают от его потери. Важные копии
переносите отдельно; личные архивы не входят в основной backup.

Проект независим от Material Indicators.
