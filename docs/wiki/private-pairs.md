# Личные пары Binance Spot

Публичная главная страница и `/api/chart` остаются только BTCUSDT. Отдельная
страница `/private` после проверки сессии даёт владельцу запуск, выбор и удаление
дополнительных пар. API `/api/private/*` проверяет роль до чтения личных данных
и любых запросов к Binance. Изменяющие запросы также проверяют Origin, тип и
ограниченный размер JSON.

## Работа

- Выбрать доступную торговую пару из `exchangeInfo` Binance Spot и нажать «Начать сбор».
- Сбор начинается с текущего момента. Между страницами и парами он продолжается.
- Показываются последние 6 часов; старые минутные данные удаляются раз в минуту.
  Для восстановления границы сырого архива остаётся минимальная опора и её час.
- Объём, нижняя/верхняя границы шкалы, ценовой шаг и диапазон задаются вручную.
  Настройки сохраняются на сервере по символу, включая случай удаления архива.
- «Остановить и удалить» сразу запрещает новые чтения выбранной пары, затем
  фоновый менеджер завершает её процесс и удаляет только её каталог. BTCUSDT
  не допускается как цель личных управляющих операций.
- До четырёх личных пар одновременно по умолчанию (`private_max_active`). Это
  ограничение ресурсов и общей нагрузки публичных REST depth5000. HTTP429/418
  и Retry-After продолжают обрабатываться сборщиком. Недостаток свободного диска
  блокирует новые старты и перезапуски личных сборщиков.

Валюта сумм — quoteAsset пары (например BTC в ETHBTC); USDT-конвертация не
придумывается. Пороговые группы CVD также относятся к валюте котировки.
Цены хранятся в целых единицах с масштабом по tickSize, до 12 знаков после
запятой. CVD личных пар хранится в стомиллионных долях валюты котировки, чтобы не терять исполнения размером в сатоши. Формат/шаг/масштаб существующего BTC-архива не меняются.
При отсутствии исполнений приватный сборщик сохраняет наблюдаемую середину
лучших bid/ask как опорную цену карты, не создавая фиктивных сделок или CVD.

## Доступ владельца

Под владельцем checkout из папки проекта:

```bash
.venv/bin/python -m mtanalog private-link --origin https://charts.example.com --output output/private-owner-link.txt
```

Команда создаёт или **отзывает прежнюю** ссылку. Токен находится только в
локальном файле 0600; в `data/private-access.json` хранится SHA256. Фрагмент
`#key=...` обменивается на Secure/HttpOnly/SameSite=Strict cookie на 30 дней и
удаляется из адресной строки до следующих действий. Без сессии — HTTP403.
Личную ссылку нельзя публиковать или включать в Git/демо.

## Процессы и файлы

- Один поток-менеджер в web с отдельным flock. Выбранные пары сохраняются в
  `data/private-pairs.json`, перезапускаются после перезапуска web.
- По одному независимому процессу `mtanalog.pairs_worker` и writer lock на
  `data/private-pairs/<SYMBOL>/archive.sqlite`; публичный writer не запускается
  повторно. Каждый процесс также ведёт свой независимый кэш свечей.
- Web читает архивы. SQL-расчёты личных графиков разделяют один compute lock,
  публичный график использует свой. Размеры матрицы/ответов/кэшей ограничены.
- Перед остановкой PID проверяются UID, модуль и точный путь конфигурации.
  Удаление не выполняется, пока проверенный writer не завершён.
- Корни данных и символы проверяются; обход пути и подмена каталога symlink
  запрещены. Роль проверяется сервером, скрытие панели не является защитой.
- Основной backup BTC не включает личные архивы, настройки и реестр доступа.
  Их нельзя считать защищёнными этим backup; шестичасовые архивы временные.

Для штатного обновления web используйте root `systemctl stop/start/restart
mtanalog-web.service`. При остановке web его личные workers завершаются;
после запуска выбранные пары возобновляются по сохранённому реестру.
Публичная / не показывает панель даже с cookie владельца. На /private панель
создаётся после серверной проверки сессии; гость перенаправляется на /.
